# Image Prompt Basics
## First Character Generation
Let's generate our first character, copy this callsheet prompt into the `Callsheet Text Input` node:
```
pipeline: character
size: 1mp 1:1
label: ninja
---
Full body character turnaround (front, side, back) in anime style of a male ninja on plain white background. The ninja has no mask, with sharp focused eyes and determined expression. He wears form-fitting black tactical attire with sleek metallic armor plates forearms, and shins. The armor features subtle engraved patterns and clean metallic finishes. His short dark hair is slightly tousled with some strands falling across his forehead. He has several kunai knives strapped to his thighs. The illustration uses clean anime line art with consistent proportions across all angles.
```
Hit run ![](images/run.png) and the resulting generation will appear in the Callsheet Collector node.

![](images/008_FirstCharacter.png)

Let's break down the callsheet prompt you copied. The whole thing is called a **block** (we can have more than one block but more on that later). Blocks are composed of two parts split by the `---` line. The first part is the **header** and the second is the **prompt**:
```
header
---
prompt
```
The **header** in the block of our callsheet was:
```
pipeline: character
size: 1mp 1:1
label: ninja
```
The properties are:
 * The `pipeline` property is set to "character" (which matches the `task` in the advanced settings `pipeline_specs` for the `krea2` pipeline), this will route our properties and prompt to our Krea-2 pipeline.
 * The `label` is what we use to reference this image in later generation and tasks.
 * And `size` is the resolution of the final image which can be specified in different ways. With the way shown, `1mp` is 1 megapixel, `1:1` is a square aspect ratio (16:9 would be wide screen). For size you could also specify a width and height instead `size: 1024x1024`.

What follows after the `---` line is the actual text prompt. I had this example partially generated by GLM 3.6 with some tweaks to target Krea 2. Specifically for character reference generation we use "Full body character turnaround (front, side, back)" and "plain white background" (note: this is why `prompt enhancer` is disabled for the Krea-2 subgraph).

## Second Character Generation

Lets generate another character, replace text with the following in the `Text Input` node:
```
pipeline: character
size: 1mp 1:1
===
label: ninja
---
Full body character turnaround (front, side, back) in anime style of a male ninja on plain white background. The ninja has no mask, with sharp focused eyes and determined expression. He wears form-fitting black tactical attire with sleek metallic armor plates forearms, and shins. The armor features subtle engraved patterns and clean metallic finishes. His short dark hair is slightly tousled with some strands falling across his forehead. He has several kunai knives strapped to his thighs. The illustration uses clean anime line art with consistent proportions across all angles.
===
label: ronin
---
Full body character turnaround (front, side, back) in anime style of a male ronin samurai on plain white background. The ronin has a weathered face with intense eyes and a well-groomed beard. His dark hair is partially tied in a loose topknot with some strands falling freely. He wears traditional dark blue samurai clothing without armor - a simple kimono top with wide sleeves, hakama pants, and a simple sash. A single katana is tucked into his sash, worn from frequent use. His clothing appears slightly worn but well-maintained, befitting a masterless warrior. The illustration uses clean anime line art with consistent proportions across all angles.
```
And hit run ![](images/run.png), to see the results which again will show up in the `Collector` node, you can browse between the ninja and ronin using the arrow buttons to the left and right of the label name.

![](images/009_SecondCharacter.png)

As mentioned before a callsheet can have lots of blocks, we changed the previous one slightly and now have 3 blocks. Blocks in callsheets are separated by `===` lines.
```
block one
===
block two
===
block three
```
So if we added only one character why 3 blocks instead of 2? Well with callsheets you can have a block that sets default settings used by blocks that follow it. Since our two character generations use the same `pipeline` and `size` we can define that ahead of time and only need to label them. The **default block** is specified without a `label` or a prompt. For **task blocks** that generate our characters they require a label.

## Variation / Seed Hunting
Let's say we get a bad generation with a prompt and we want to try random seeds. You can press the `+ variation` on the `Collector` to generate one or more variations.

![](images/010_Variations.png)

The variations appear at the bottom and you can select the one you want to use for references later on.

Tip: It's worth pointing out that variations and selections are stored in the advanced settings of the connected `Callsheet Text Input` node. So they are saved as part of the workflow. You can delete them to reset or manually modify them.

## More on Pipelines

The word 'pipeline' is somewhat of an overloaded term with this system, in the callsheet prompt it is meant to be a kind of task directed at pipelines. We called the previous one "character". We could have just called it "krea2" but the idea is if an LLM were to generate the callsheet prompt itself it may not be aware of what model you are using for character generation. In fact you may use the same model to handle other text to image generation tasks like for backgrounds.

Outside of the callsheet prompt 'pipeline' refers to the task handler, the graph connected to the `Callsheet Pipeline Basic` node itself, which is the Krea-2 subgraph.

In a callsheet workflow tasks are set in the advanced settings `pipeline_specs`, this is where you will find the available tasks specified.

![](images/pipeline_specs.png)

In there you see `character`, `background`, and `prop` `tasks` that produce an `image`.

That means anytime `pipeline: background` is encountered in our callsheet prompt, it will be handled by our Krea-2 subgraph.

So let's add this to our example callsheet prompt in the `Callsheet Text Input` node:
```
===
pipeline: background
size: 1mp 3:1
===
label: grocery_store
---
Cross-section view in anime background style of a grocery store. In the back is a soda isle. At the center is a table. On the right are some neatly stacked boxes.

```
Hit run ![](images/run.png) and see the results in the `Callsheet Collector` node using the arrows to examine it.

![](images/012_Background.png)

Breaking down the text added to the callsheet, you will notice there are two blocks. The first `===` line separates us from the last character block. In the first of our new blocks we changed the default `pipeline` to "background" and set the size to be a very wide image to cover a larger area of the background. The prompt also uses "Cross-section view", something Krea-2 understands, to give us a nice side view of the background and not so much perspective, sort of like what you would expect to see on a set of a tv show or movie.

Let's also do a prop by adding this to our callsheet:
```
===
pipeline: prop
size: 1mp 1:1
===
label: bottle
---
Anime style illustration of a tall transparent plastic bottle with green cap and filled with yellow liquid contents.
```
And run ![](images/run.png):
